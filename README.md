# Pangool Diviner — Setup & Operations

> **Audience:** this README is written for an LLM coding agent (or a human comfortable reading dense, structured docs). It contains every command, path, env var, and artifact required to bring the installation up from a clean macOS machine. Follow top-to-bottom.

An offline AI oracle museum installation (Bildmuseet, 11 months). An iPad kiosk displays a divination generated by a locally-hosted fine-tuned Gemma model and spoken through a sculpture speaker.

---

## 1. System Overview

```
iPad (Safari, Guided Access)  ──Ethernet──  Mac Mini (server)  ──3.5mm──  Speaker
         10.0.0.2                                10.0.0.1
```

| Component | Host | Purpose |
|---|---|---|
| React SPA (Vite build) | Mac Mini, served by FastAPI at `:8000` | iPad UI |
| FastAPI backend (`backend/main.py`) | Mac Mini, port `8000` | `/api/divine`, `/api/speak`, `/api/transcribe`, `/api/health` |
| Ollama | Mac Mini, port `11434` | Hosts the fine-tuned `pangool` model |
| Afro-TTS (XTTS v2) | Mac Mini, in-process with FastAPI | Voice-cloned speech synthesis |
| faster-whisper (optional) | Mac Mini, in-process | STT for spoken questions |
| launchd | Mac Mini | Autostart, crash recovery, nightly reboot |

**Invariants**
- Fully offline at runtime. Internet is only required during initial setup.
- Mac Mini's 3.5mm jack is the only audio output. iPad produces no sound.
- Static IPs on the direct Ethernet link: Mac `10.0.0.1`, iPad `10.0.0.2`.

## 2. Required Downloads (Not in Git)

These files are too large or too custom to commit. The operator downloads them **manually from Google Drive** and places them at the paths below before running setup. The setup scripts assume these files are already in place — they will not fetch them.

**Source location:** `Pangool` shared drive (Unpaid Labour Google Workspace) → `deploy assets/`. The Drive folder mirrors the repo layout — its `models/` and `voices/` subfolders drop directly into the project root.

```
Pangool (shared drive)
└── deploy assets/
    ├── models/          →  copy into pangool_ipad_app/models/
    │   └── pangool_exp06.gguf
    └── voices/          →  copy into pangool_ipad_app/voices/
        ├── pangool_reference.wav
        ├── pangool_reference1.wav
        └── pangool_reference2.wav
```

| Artifact | Place at exactly this path | Size (approx) | Source | Notes |
|---|---|---|---|---|
| **Fine-tuned Gemma GGUF** | `models/pangool_exp06.gguf` | ~3 GB | Google Drive (operator-provided) | Custom fine-tune of Gemma 3. Referenced by `models/Modelfile.local` as `./pangool_exp06.gguf`. |
| **Reference voice WAV (primary)** | `voices/pangool_reference.wav` | ~1–3 MB | Google Drive (operator-provided) | 6–15 s clean speech clip used as XTTS voice-cloning target. **Required** — TTS will fall back to macOS `say` without it. |
| **Reference voice WAVs (alt)** | `voices/pangool_reference1.wav`, `voices/pangool_reference2.wav` | ~1–3 MB each | Google Drive (operator-provided) | Optional variants. Only `pangool_reference.wav` is loaded by default (override via `PANGOOL_REFERENCE_WAV`). |
| **Afro-TTS model files (5)** | `models/afrotts/{config.json, model.pth, vocab.json, mel_stats.pth, dvae.pth}` | ~2 GB total | HuggingFace `intronhealth/afro-tts` — handled by `scripts/download-afrotts.sh` | Public, scripted. |
| **Base Gemma (fallback)** | Ollama-managed | ~3 GB | `ollama pull gemma3:4b` | Optional fallback if the fine-tune is unavailable; requires editing `backend/inference.py` `MODEL_NAME`. |
| **Whisper tiny** | `~/.cache/huggingface/` (auto) | ~75 MB | auto-downloaded on first `/api/transcribe` | Needs internet on first STT call. |

**Operator checklist before running §4:**
1. Open the `Pangool` shared drive → `deploy assets/`.
2. Download the `models/` and `voices/` subfolders (or their contents).
3. Merge them into the project root so you end up with `pangool_ipad_app/models/pangool_exp06.gguf` and `pangool_ipad_app/voices/pangool_reference.wav` (plus alternates).
4. Verify exact filenames and paths match the table above — the Ollama Modelfile and `backend/tts.py` hardcode these names.

```bash
# Quick verification after placing files manually:
ls -lh models/pangool_exp06.gguf voices/pangool_reference.wav
```

## 4. One-Shot Setup (Mac Mini)

Run these in order from the project root (`pangool_ipad_app/`). Each block is idempotent — safe to re-run.

### 4.1 Clone & enter

```bash
git clone <repo-url> pangool_ipad_app
cd pangool_ipad_app
mkdir -p logs models voices models/afrotts
```

### 4.2 Place the operator-supplied artifacts (see §2)

**This step is manual — not scripted.** Before proceeding, the operator must have already downloaded the restricted files from Google Drive and placed them at:

- `models/pangool_exp06.gguf`
- `voices/pangool_reference.wav`

Verify:

```bash
test -f models/pangool_exp06.gguf    && echo "GGUF OK"    || echo "MISSING: models/pangool_exp06.gguf"
test -f voices/pangool_reference.wav && echo "voice OK"   || echo "MISSING: voices/pangool_reference.wav"
```

If either reports MISSING, stop and obtain the file from the operator's Google Drive before continuing — `ollama create` (§4.6) and Afro-TTS loading (§4.7) will fail without them.

### 4.3 Download Afro-TTS (public, scripted)

```bash
bash scripts/download-afrotts.sh
# Produces: models/afrotts/{config.json, model.pth, vocab.json, mel_stats.pth, dvae.pth}
```

### 4.4 Backend deps

```bash
cd backend
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cd ..
```

`requirements.txt` pins:
- `fastapi==0.115.6`, `uvicorn[standard]==0.34.0`, `sse-starlette==2.2.1`, `httpx==0.28.1`, `python-multipart==0.0.20`
- `coqui-tts[codec]>=0.22.0`, `torchaudio`, `soundfile>=0.12.0`
- `faster-whisper==1.1.0`

### 4.5 Frontend build

```bash
cd frontend
npm install
npm run build        # → frontend/dist/ (served as static by FastAPI)
cd ..
```

### 4.6 Register the Ollama model

Ollama reads the Modelfile and registers a model named `pangool` (this name is hardcoded in `backend/inference.py:MODEL_NAME`).

```bash
ollama serve &                        # background, or let launchd handle it later
ollama create pangool -f models/Modelfile.local
ollama list                           # verify "pangool" appears
```

`models/Modelfile.local` references `./pangool_exp06.gguf` and bakes in the Serer-proverb system prompt and Gemma chat template.

### 4.7 Smoke-test the backend (manual)

```bash
cd backend && source .venv/bin/activate
uvicorn main:app --host 0.0.0.0 --port 8000
```

Then, from another shell:

```bash
curl http://localhost:8000/api/health
# expect: {"status":"ok","service":"pangool"}

curl -N -X POST http://localhost:8000/api/divine \
     -H 'Content-Type: application/json' \
     -d '{"theme":"fortune"}'
# expect: SSE stream of "token" events, then a "done" event

curl -X POST http://localhost:8000/api/speak \
     -H 'Content-Type: application/json' \
     -d '{"text":"The ancestors speak."}'
# expect: audio plays on Mac Mini speaker, returns {"status":"ok",...}
```

Stop uvicorn with Ctrl-C once verified.

### 4.8 Install launchd services + system tweaks

```bash
sudo bash scripts/setup-mac.sh
```

This script:
1. Disables sleep / display sleep / disk sleep; sets `autorestart=1` for power-failure recovery.
2. Disables macOS software updates & screensaver.
3. Installs three launch agents to `~/Library/LaunchAgents/`, substituting `__PANGOOL_DIR__` with the project's absolute path:
   - `com.pangool.backend.plist` — runs `uvicorn main:app --host 0.0.0.0 --port 8000`
   - `com.pangool.ollama.plist` — runs `ollama serve` with `OLLAMA_HOST=127.0.0.1:11434`
   - `com.pangool.nightly-reboot.plist` — reboots at 03:00 local time daily
4. Rebuilds `frontend/dist/`.

Note: the plists assume binaries at `/usr/local/bin/uvicorn` and `/usr/local/bin/ollama`. On Apple Silicon, Homebrew installs to `/opt/homebrew/bin/` — check `which uvicorn` / `which ollama` and edit the plists if needed. `PATH` in the plists already includes `/opt/homebrew/bin`, but the hardcoded `ProgramArguments` paths do not.

Verify:

```bash
launchctl list | grep pangool
# expect three entries
```

### 4.9 Static IP on Ethernet (manual)

System Settings → Network → Ethernet → Details → TCP/IP → Configure IPv4: **Manually**
- IP: `10.0.0.1`
- Subnet mask: `255.255.255.0`
- Router: (leave blank)

## 5. iPad Setup

Full instructions in [`scripts/setup-ipad.md`](scripts/setup-ipad.md). Summary:

1. Connect iPad via USB-C→Ethernet adapter to the Mac Mini.
2. **Settings → Ethernet → Configure IP → Manual**: IP `10.0.0.2`, mask `255.255.255.0`.
3. Turn off Wi-Fi, Bluetooth, notifications, auto-lock, auto-update, Screen Time.
4. Safari → `http://10.0.0.1:8000` → verify the app loads.
5. Enable Guided Access (**Settings → Accessibility → Guided Access**), set a passcode.
6. Triple-click Top Button → Guided Access → Options (Touch ON, Motion/Keyboards OFF, no time limit) → Start.

## 6. Runtime Behaviour

### Service topology (once launchd is loaded)

```
launchd
  ├── com.pangool.ollama       ── ollama serve (11434)
  ├── com.pangool.backend      ── uvicorn main:app (8000, KeepAlive=true)
  └── com.pangool.nightly-reboot  (03:00 daily)
```

### Request lifecycle — `/api/divine`

1. iPad POSTs `{theme, question?}` with `Accept: text/event-stream`.
2. `backend/inference.py:generate_divination` picks a random training-theme word from the pool matching the iPad domain (e.g. `work` → `"Skill"`).
3. Streams to Ollama `/api/generate` with `model="pangool"`.
4. Yields each character as SSE `event: token` for the frontend typewriter.
5. On stream end, emits `event: done` with the full text and logs via `divination_log.py`.

### Request lifecycle — `/api/speak`

1. `tts.py:synthesize` runs XTTS inference using pre-computed voice-conditioning latents from `voices/pangool_reference.wav` (overridable via `PANGOOL_REFERENCE_WAV`).
2. Writes a temp WAV at 24 kHz.
3. `audio.py:play_audio` plays it through system default output (`afplay`).
4. Falls back to macOS `say` → `afconvert` if Afro-TTS failed to load.

### Device selection (TTS)

`tts.py` picks in order: MPS (Apple Silicon) → CUDA → CPU. Mac Mini M-series hits MPS automatically.

## 8. API Reference

| Method | Path | Body | Response |
|---|---|---|---|
| `GET`  | `/api/health` | — | `{"status":"ok","service":"pangool"}` |
| `POST` | `/api/divine` | `{"theme":"fortune","question":"..."?}` | SSE: repeated `event: token` with `{token: "x"}`, then `event: done` with `{full_text}`, or `event: error` |
| `POST` | `/api/speak` | `{"text":"..."}` | `{"status":"ok","message":"..."}` — plays audio on Mac Mini |
| `POST` | `/api/transcribe` | multipart `audio` (WAV/WebM) | `{"status":"ok","text":"..."}` |
| `GET`  | `/*` (non-API) | — | Serves `frontend/dist/index.html` |

Valid `theme` values (see `backend/inference.py:THEME_POOLS`): `work`, `love`, `health`, `fortune`, `growth`, `being`. Unknown values fall back to `fortune`.

## 10. Development Mode

Run backend and frontend separately with hot reload:

```bash
# Terminal 1
cd backend && source .venv/bin/activate
uvicorn main:app --host 0.0.0.0 --port 8000 --reload

# Terminal 2
cd frontend
npm run dev       # http://localhost:5173, proxies /api → :8000
```

Ollama must also be running: `ollama serve`.

## 11. Troubleshooting Matrix

| Symptom | Likely cause | Check / fix |
|---|---|---|
| iPad shows "the pangool is resting…" | Backend unreachable | `curl http://10.0.0.1:8000/api/health` from another machine; verify Ethernet cable; `launchctl list \| grep pangool.backend` |
| `/api/divine` returns 500 | Ollama down or model missing | `curl http://localhost:11434/api/tags` and confirm `pangool` is listed; if not, re-run `ollama create pangool -f models/Modelfile.local` |
| No audio from speaker | TTS failed or wrong output device | Check `logs/backend.error.log`; verify 3.5mm cable; on Mac: `System Settings → Sound → Output` → headphones/line-out |
| `tts.py` logs "Failed to load Afro-TTS" | Missing or corrupt files in `models/afrotts/` | Re-run `bash scripts/download-afrotts.sh`; confirm all 5 files exist with non-zero size |
| `tts.py` logs "reference WAV missing" | `voices/pangool_reference.wav` absent | Re-download per §2 or set `PANGOOL_REFERENCE_WAV` to an existing file |
| launchd service flapping | Wrong binary path in plist | Apple Silicon: `ls /opt/homebrew/bin/{uvicorn,ollama}`; edit plists in `~/Library/LaunchAgents/` and `launchctl unload && launchctl load` |
| `/api/transcribe` returns null | Whisper model never downloaded | First call requires internet; check `logs/backend.error.log` for faster-whisper download errors |
| Frontend shows blank page in prod | `frontend/dist/` missing | `cd frontend && npm run build` |
